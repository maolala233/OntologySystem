# 双路溯源问答实现指南

## 概述

本系统实现了**双路溯源问答**（Dual-Path RAG），融合 Neo4j 图检索和 Milvus 向量检索，提供精准回答和完整的溯源信息。

---

## 核心架构

```
用户问题 + 知识域过滤
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│                    双路 RAG 引擎                          │
├─────────────────────────────────────────────────────────┤
│  ┌────────────────────────────────────────────────────┐ │
│  │ 路径 A：Neo4j 结构化图检索                           │ │
│  │ 1. 获取当前项目的 Schema (类的列表、关系列表)         │ │
│  │ 2. 调用 LLM (Text2Cypher) 生成 Cypher 查询语句       │ │
│  │ 3. 在 Neo4j 中执行 Cypher，获取精确的关系图谱路径     │ │
│  └────────────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 路径 B：Milvus 语义向量召回                          │ │
│  │ 1. 构建过滤表达式 (domain in [...], project_id=?)   │ │
│  │ 2. 向量召回 Top_K 切片                              │ │
│  │ 3. 提取完整原文 (chunk_text) 和 原句引用 (source_quote)│ │
│  └────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
         │
         ▼
【智能上下文融合】
拼接 Neo4j 的确凿事实 + Milvus 的丰富文本
         │
         ▼
【最终 LLM 生成】
根据融合的上下文回答问题，并打上引用标号 [1][2]
         │
         ▼
输出：精准回答 + 双路溯源 Reference
```

## 2. Neo4j 图数据库的存储结构

### 2.1 节点 (Node) 的实际存储

```cypher
(:NamedIndividual :理财产品 {
    id: "I_a1b2c3d4",
    label: "阳光橙安盈",
    project_id: 101,                  // [索引] 用于多租户隔离
    domain: "理财业务",               // [索引] 用于联邦检索隔离
    
    // 业务属性
    风险等级："R2",
    成立日期："2024-01-01",
    
    // 溯源属性
    source_file: "阳光橙说明书.pdf",
    source_chunk_index: 12,
    source_quote: "该产品名为阳光橙安盈，风险等级为 R2。"
})
```

### 2.2 关系/边 (Edge) 的实际存储

```cypher
()-[:由机构管理 {
    project_id: 101,
    domain: "理财业务",
    source_file: "阳光橙说明书.pdf",
    source_chunk_index: 15,
    source_quote: "阳光橙安盈由中信银行担任主要管理人。"
}]->()
```

### 2.3 关键代码：`neo4j_client.py`

```python
@staticmethod
def _create_node_with_provenance(tx, project_id, node_data, domain: str = None):
    """创建节点，包含溯源信息"""
    properties = node_data.get("data", {}).get("properties", {}) or {}
    
    # 从 properties 中提取溯源信息 (移除 _ 前缀)
    source_file = properties.get("_source_file")
    source_chunk_index = properties.get("_source_chunk_index")
    source_quote = properties.get("_source_quote")
    
    if source_file:
        props["source_file"] = source_file
    if source_chunk_index is not None:
        props["source_chunk_index"] = int(source_chunk_index)
    if source_quote:
        props["source_quote"] = source_quote
```

### 4.2 关键代码：`rag_engine.py`

```python
def query(self, question: str, project_id: int, domains: List[str] = None, ...) -> Dict:
    # ========== 路径 A：Neo4j 图检索 ==========
    graph_facts, graph_references = self.neo4j_client.query_with_provenance(...)
    
    # ========== 路径 B：Milvus 向量检索 ==========
    vector_results = self.vector_store.search_with_expr(...)
    vector_references = self._extract_references(vector_results)
    
    # ========== 智能上下文融合 ==========
    fused_context = self._fuse_context(graph_facts, vector_results)
    
    # ========== 最终 LLM 生成 ==========
    answer, references = self._generate_answer_with_references(
        question, fused_context, graph_references, vector_references
    )
    
    return {
        "answer": answer,
        "references": references,
        "debug_info": {...}
    }
```

## 5. 完整联动流程

### 5.1 数据入库流程

```
┌─────────────────────────────────────────────────────────────┐
│ 步骤 1: 用户上传文档 (PDF/Word/TXT)                            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤 2: 调用 OntologyExtractor.extract_instances()          │
│ - 将文档切分为多个 chunk，每个 chunk 携带 (filename, chunk_index) │
│ - LLM 提取实例，每个实例注入溯源锚点：                            │
│   - _source_file: 文件名                                      │
│   - _source_chunk_index: 切片索引                              │
│   - _source_quote: 原句摘抄                                    │
│   - _domain: 知识域                                            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤 3: 同步到 Neo4j (neo4j_client.sync_graph())            │
│ - 创建节点，将溯源信息存储为节点属性                              │
│ - 创建关系，将溯源信息存储为关系属性                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤 4: 同步到 Milvus (vector_client.insert_data())         │
│ - 构建向量，存储 chunk_text 和 source_quote                     │
│ - 设置标量索引：project_id, domain, source_file              │
└─────────────────────────────────────────────────────────────┘
```

│ ┌──────────────────────────────────────────────────────────┐│

┌─────────────────────────────────────────────────────────────┐
│ 步骤 4: LLM 生成回答                                          │
│ - 根据融合上下文生成回答                                      │

## 8. 总结

双路溯源问答的核心优势：

1. **Neo4j 路径**：提供确凿的结构化事实，适合回答精确的关系查询
2. **Milvus 路径**：提供丰富的文本上下文，适合回答需要详细解释的问题
3. **双路融合**：结合两者优势，提供更全面、准确的回答
4. **完整溯源**：每个回答都有明确的来源标注，支持前端高亮展示和原文定位
