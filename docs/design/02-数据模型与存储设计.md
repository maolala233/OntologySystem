# 02 · 数据模型与存储设计

> 目标：把现有 5 张表（`users`、`projects`、`knowledge_domains`、`system_configs`、`uploaded_documents`）演进为 **20 张表**，承担身份权限、模型配置、文档与切片、本体数据行表、治理（溯源/审核/冲突）、版本发布、Outbox、审计、MCP 令牌全部元数据；本体数据本体（节点/边）在 Neo4j/Milvus/Oxigraph 三类存储中持久化，MySQL 只保留行表索引与投影。
>
> 迁移一律走 Alembic（首次引入），删除 `database.py` 中的 `_auto_migrate`。

---

## 1. 存储职责矩阵（需求 6）

| 存储 | 承载内容 | 写入者 | 一致性来源 |
|------|---------|--------|-----------|
| **MySQL 8**（3309，utf8mb4） | 用户/权限/模型配置/项目/知识域/文档与分块/实体关系行表/溯源/审核/版本/发布/Outbox/审计/布局缓存 | API + workers | 唯一事实源（SoT） |
| **Neo4j 5.26**（LPG） | TBox 类/关系 + ABox 实例 + 溯源属性 +（可选 n10s RDF 桥） | worker-graph（outbox 消费） | outbox 幂等 MERGE |
| **Milvus 2.3**（向量） | 实例与分块语义向量（bge-m3 1024 维），知识域/项目分区过滤 | worker-graph（outbox 消费） | 主键 = 确定性 ID，xxhash 内容去重 |
| **Oxigraph 嵌入式**（RDF/SPARQL） | TBox 命名图 / ABox 命名图 / 溯源命名图（PROV-O）/ 发布快照命名图 | worker-rdf（concurrency=1，唯一写者） | outbox 幂等 + 命名图整体替换 |
| **MinIO** | `ontology-uploads`（原件）/ `ontology-parsed`（解析全文、快照 JSON、预布局结果、导出产物）/ `ontology-exports`（成品导出） | API（上传）/ workers（产物） | 对象键不可变，元数据在 MySQL |

原则：**任何跨库写入都由 `outbox_events` 驱动**（事务性 Outbox），API 进程只写 MySQL；Neo4j/Milvus/Oxigraph 不再被 API 进程直写（现有 `api/ontology.py` 里的同步调用全部移入 worker）。

## 2. 表分组总览

```
身份与权限   users · modules · user_module_grants · project_members
模型配置     model_configs
业务主体     projects · knowledge_domains
文档与切片   uploaded_documents · document_chunks
本体行表     entities · relations
治理         provenance_records · review_items
版本与发布   ontology_versions · graph_snapshots · publications
基础设施     outbox_events · audit_logs · graph_layouts
（system_configs 保留：仅存平台级杂项，模型配置迁出至 model_configs）
```

通用约定：所有表 `id BIGINT AUTO_INCREMENT PK`；时间戳 `created_at/updated_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3)`（`ON UPDATE` 视语义）；软删只用于 `projects`/`uploaded_documents`（`deleted_at`），其余物理删；JSON 列用 `JSON` 类型；引擎 InnoDB。

## 4. graph_data blob → 行表迁移（三阶段双写）

现有 `projects.graph_data`（整块 JSON）是图渲染与导出的唯一来源，迁移分三阶段，全程不停止服务：

| 阶段 | 动作 | 读方 | 写方 |
|------|------|------|------|
| **S1 双写** | 行表建好；抽取/画布编辑在写 blob 的同时拆写 `entities`/`relations`；存量项目跑一次性回填任务（Celery `graph` 队列，按项目逐个） | 仍读 blob | 双写（blob 为准，行表对账） |
| **S2 切读** | 对账脚本（行表 vs blob 的节点/边计数与 URI 集合 diff）通过后，图谱/导出/消解读行表；blob 仅兜底 | 读行表 | 双写（行表为准，blob 兜底） |
| **S3 下线** | 版本快照与发布快照改为指向行表导出物；`graph_data`/`ttl_content` 列保留只读一版后删除 | 读行表 | 行表 |

对账 SQL 口径：`COUNT(entities)=COUNT(blob.nodes)`、`COUNT(relations)=COUNT(blob.edges)`、`(SELECT GROUP_CONCAT(uri) ORDER BY uri)` 与 blob label 集合 diff 为空。

## 5. Outbox 单写者模式（需求 6 核心）

```
API 事务: UPDATE entities ... + INSERT outbox_events (同一事务)
   │
worker-graph 消费(event: entity.upsert / relation.upsert / *.delete / chunk.vectorize)
   ├─ Neo4j: MERGE (n:Resource {uri:$uri}) ON CREATE SET ... ON MATCH SET ...
   │         project_id 属性必写；删除按 uri 精确 DETACH DELETE
   └─ Milvus: upsert(pk=uri_hash)；向量化失败→status=failed+重试(退避 1/5/15min)
worker-rdf 消费(event: ttl.rebuild / publication.created)   ← concurrency=1
   └─ Oxigraph: 命名图整体替换
       GRAPH <urn:onto:{project}:tbox>  TBox 三元组
       GRAPH <urn:onto:{project}:abox>  ABox 三元组
       GRAPH <urn:onto:{project}:prov>  PROV-O 溯源三元组
       GRAPH <urn:onto:{project}:pub:{version_no}>  发布快照（不可变）
```

- **幂等**：消费端以 `(aggregate_type, aggregate_id, event_type)` 幂等键去重；Neo4j MERGE / Milvus upsert 天然幂等；RDF 用"命名图重建"而非增量三元组追加。
- **重放**：清空 Neo4j 项目子图/Milvus 分区/RDF 命名图后，从 `entities/relations/chunks` 全量重新产生 outbox 事件即可完整重建三类存储（灾备与迁移演练路径）。
- **顺序**：同一 aggregate 的事件按 `id` 顺序消费；`entity.merge` 事件必须晚于被合并实体的 `upsert`（生产端保证）。

## 6. Alembic 迁移分批

## 8. 备份与恢复

- MySQL：每日 `mysqldump --single-transaction`（beat 触发脚本落 MinIO `backup/` 前缀，保留 14 天）。
- Oxigraph：worker-rdf 在每日快照后复制数据目录（停写窗口 < 5 s：暂停消费→copy→恢复）。
- Neo4j/Milvus：依赖 outbox 重放能力（§5）做逻辑重建，不要求物理备份（单机盘损坏场景走 MySQL 快照 + 重放）。
