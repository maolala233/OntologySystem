### 1.2 主要问题（重构动机）

**正确性/数据质量**
- 抽取链路 14 项缺陷（4 个 P0，详见 `docs/抽取优化方案.md` 与本方案 04 §11）：前缀去重误合并（`合同2024`→`合同`）、schema prompt 结构丢失、metadata 成功率造假、类型子串错配。
- 实体消解对中文几乎失效（`names_are_similar` 是 snake_case 相等比较）。
- 无独立冲突检测模块。

**平台能力缺口**
- `User` 无 role 字段，admin 靠 `username == "admin"` 硬编码（`api/auth.py:157` 等 8 处）；无模块级授权、无项目成员。
- 无版本控制（`ttl_content` 直接覆盖）、无审核队列、无发布快照（发布后仍可编辑）。
- RDF 仅为内存 TTL 字符串，无 triple store 持久化。
- 抽取任务跑在 API 进程内（fire-and-forget + 进程内 TaskManager，重启即丢）。
- 无 MCP；问答仅一套双路 RAG（无图扩展升级路径）。

**工程与安全**
- 旧 `/api/v1/*` 多数端点无鉴权（rag/files/update-ontology/sync-ttl）。
- CORS `allow_origins=["*"]`；外网 API 代理硬编码 `127.0.0.1:7890`；种子密码打印日志。
- `extractor.py` 3906 行、`api/ontology.py` 4221 行、前端 `OntologyBuilderPage.tsx` 3837 行，sync/async 双实现 91% 重复。
- 前端图谱：D3-force + SVG 上限约 1–2k 节点；布局含 `Math.random()` 噪声不可复现；孤立节点右抛；中文标签截断 5–6 字；无 LOD/搜索/过滤；两套图实现（D3ForceGraph + 已弃用 OntologyCanvas）并存。

### 3.1 依赖规则（适配层铁律）

```
api → services → tasks → adapters → semantica
                ↘ infrastructure(自有客户端) ↗
禁止：api/services/tasks → semantica（直接 import）
禁止：adapters → api/services（反向依赖）
```

- Semantica 以 `pip install "semantica[all]"` 固定版本 `semantica==0.7.*`，版本升级只允许发生在 `adapters/_compat.py`（集中处理 API 变化与中文补丁）。
- 适配层对外暴露**平台自己的类型**（Pydantic 模型），不把 Semantica 的数据类泄漏到服务层之外。

## 4. 技术选型

### 4.1 保留不动

| 项 | 选型 | 理由 |
|----|------|------|
| 后端框架 | FastAPI + SQLAlchemy 2 | 现有全部业务在此，语义上与 Semantica（Python）同进程成本最低 |
| 关系库 | MySQL 8（3309，utf8mb4） | 已运行；治理类数据强一致需求 |
| 图库 | Neo4j 5.26 + APOC + n10s | 已运行且已装 RDF 插件（RDF→LPG 桥可用） |
| 向量库 | Milvus 2.3.5 | 已运行；Semantica 有官方 MilvusStore |
| 队列 | Redis 7 + Celery | 中间件已按此预配置（AOF、noeviction） |
| 文件存储 | MinIO（ontology-uploads/parsed/exports 三桶） | 中间件已建桶 |
| 前端框架 | React 18 + antd 5 + Vite + Tailwind | 已运行；不为图谱重构升级 React 19（Sigma 3 兼容 18） |
| RDF | **嵌入式 pyoxigraph**（Semantica OxigraphStore） | 无需容器；中间件文件已论证 RocksDB 独占锁→单写者 |

### 4.2 新增

| 项 | 选型 | 理由 |
|----|------|------|
| 本体引擎 | `semantica[all]==0.7.*` | 消解/冲突/溯源/版本/导出/存储接口/MCP 全套，MIT |

| 前端数据层 | @tanstack/react-query v5 + zustand v5 | 现状无状态库，页面间重复拉取、50 个 useState 失控 |
| 图渲染 | sigma@3 + graphology + graphology-layout-forceatlas2 + graphology-communities-louvain + @sigma/edge-curve + @sigma/node-border | semantica-explorer 同栈，WebGL 万级节点 |

| 时间轴 | vis-timeline + vis-data | 版本时间轴与双时间轴展示 |
| i18n | react-i18next + i18next-browser-languagedetector | 需求 8；zh-CN 为默认与唯一完整语言 |
| OCR | docling（Semantica DoclingParser 后端） | 扫描件 PDF/图片；VL 模型保留为第二兜底 |
| 密钥加密 | cryptography AES-256-GCM | model_configs.api_key 落库加密 |

### 4.3 明确不引入

- **不引入** Qdrant/Weaviate（Milvus 够用）、Kafka、K8s、微服务拆分（单机生产目标）、GraphQL。
- **不引入** semantica-explorer 的 Python 后端进程（内存会话图、无多租户，与平台权限模型冲突）；只移植其前端模块（见 06）。
- **不引入** spaCy 中文模型作为主抽取路径（Semantica 的 pattern/NER 方法对中文失效，见 04 §10）。

## 7. 数据流总览（一次完整构建）

```
上传 → MinIO(uploads) → [parse] Docling解析/OCR → 全文入 MinIO(parsed)
     → [parse] 中文切片 chunk(2000/15%) → document_chunks
     → [extract] Schema 阶段：逐 chunk LLM 抽取 → SchemaGate 归并 → 画布人工修订
     → 存 ontology_versions(v1 schema)
     → [extract] Instance 阶段：SchemaGate 闸门 + 证据定位
     → [extract] 消解三层 → 冲突检测 → review_items(低置信/冲突/重复)
     → 人工审核裁决 → entities/relations 落 MySQL
     → outbox_events → [graph] Neo4j/Milvus 同步 → [rdf] Oxigraph 命名图
     → 版本快照 graph_snapshots → 发布 publications(公共区只读)
     → 消费端：图谱探索(Sigma) / 导出 / 问答(AgentContext) / MCP
```

## 8. 安全设计总则

1. **认证**：JWT（HS256，2h 有效期 + refresh 7d）；SSE 用一次性 ticket（Redis 存 60s TTL），替代现在的 `?token=` 长令牌。
2. **授权**：所有端点必须挂 `require_module(...)` 或项目角色守卫；`/admin/*` 挂 `require_role("admin")`。
3. **密钥**：`model_configs.api_key_encrypted` AES-256-GCM，主密钥来自环境变量 `SECRET_MASTER_KEY`；任何 API 响应不回显明文（只回 `sk-***last4`）。
4. **CORS**：显式白名单（默认 `http://localhost:5173,http://localhost:3080`），删除 `*`。
5. **上传安全**：扩展名 + MIME 双校验、文件名 UUID 化、MinIO 私有桶 + 预签名 URL 下载。
6. **审计**：登录、授权变更、模型配置变更、发布/回滚、审核裁决、MCP 写操作全部写 `audit_logs`。
7. **注入防护**：Text2Cypher 只允许只读查询（拒绝 CALL/CREATE/DELETE/SET），LLM 输出经白名单校验后执行。
8. **遗留收口**：删除无鉴权的 `/api/v1/*`；种子用户改为首次启动随机密码打印一次并强制改密。

## 9. 非功能性需求与验收指标

| 类别 | 指标 | 目标 |
|------|------|------|
| API 延迟 | 非抽取类 CRUD P95 | < 300 ms |

## 10. 风险与权衡

| 风险 | 应对 |
|------|------|
| Semantica 迭代快（0.6.x→0.7.x API 有变化） | `_compat.py` 集中兼容 + 版本 pin + 适配层隔离，升级只改一处 |
| 嵌入式 Oxigraph RocksDB 独占锁 | 唯一写者 worker-rdf；消费端只读（SPARQL 经 API 层代理） |
| 中文 NER 质量 | 全走 LLM 方法；金样本回归集（04 §11）守住质量 |
| Milvus 2.3.5 稳定性（etcd 租约问题） | 保持 compose 的 restart/内存约束；规划升级 2.3.20+（独立变更，不进本方案里程碑） |
| React 18 与 Sigma 3 兼容 | 官方支持；不加 React 19 兼容补丁依赖 |
| 大图（>25k）力导向卡顿 | 三级策略：实时 FA2 → 渐进渲染 → 服务端预布局（06 §10） |
