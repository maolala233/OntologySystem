# 08 · 实施路线与投喂指引

> 把方案切成 6 个里程碑（M0–M5），每期带**任务清单、涉及文档章节、验收门槛**。vibe coding 时一期一投喂（提示词模板见 §4），验收不过不进下期。


## 2. 各里程碑任务清单与验收门槛

### M0 · 地基与适配层骨架

**任务**
1. 后端装依赖 `semantica[all]==0.7.*`、alembic、celery[redis]、minio、cryptography；`requirements.txt` 更新。
2. Alembic 初始化 + R1 baseline（现状 5 表）；`init_db` 精简为 alembic + 种子。
3. `core/exceptions.py` 统一错误码（03 §2.3）；`core/deps.py` 骨架；`core/security.py` AES-256-GCM。
4. `app/adapters/` 13+1 文件骨架（空实现 + 类型定义 + `__all__`）；`_compat.py` 写入 semantica 版本探测与中文补丁清单。
5. `app/tasks/celery_app.py`：四队列 + 路由 + beat；Redis 进度键 helper。
6. 删除 CORS `*` → 白名单；删除代理硬编码（llm_client.py:101）。
7. CI：`ruff + mypy(宽松) + pytest` 契约测试骨架；前端 `tsc && vite build` 门禁。

**验收**：应用服务启动后（中间件位于 192.168.209.128，连接串经 .env 注入）`GET /api/system/health` 五灯全绿；alembic upgrade/downgrade 双向通过；pytest 冒烟绿；semantica 可 import 且版本探测正确。

### M1 · 权限与用户（需求 1）

**任务**：02 §3.1 四表迁移（R2）→ `require_module/require_role/require_project_role` 实现 → auth 扩展（refresh token、me、sse-ticket）→ admin 用户/模块授权 API（03 §3–4）→ 权限矩阵契约测试 → 前端：RequireModule 守卫、AppLayout 菜单 modules 化、`/admin/users`、`/admin/modules`（05 §6.10）→ 全库清除 `username=='admin'`（后端 8 处 + 前端 2 处）。

**验收**：普通用户登录只见默认模块菜单；未授权调 API 得 403 `MODULE_NOT_GRANTED`；管理员勾选矩阵保存后用户重新登录菜单即时变化；契约测试覆盖 admin/授权/未授权 × 5 类端点；旧硬编码 grep = 0。

### M2 · 模型配置（需求 2）

**任务**：02 §3.2 迁移（R3）→ `adapters/provider.py`（解析优先级：请求级→项目→全局→env）→ model_configs API + 连通性测试聚合端点（03 §5）→ `system_configs.llm_config/vl_config` 一次性迁移脚本 + 读取方切换（_build_extractor/QA/vl_parser/VectorStoreManager）→ 前端 `/admin/model-configs` + provider 动态表单 + 测试连接（05 §6.10），构建器内 ModelPicker → 删除两处重复 Modal。

**验收**：Ollama 本地与远程 OpenAI 兼容两种 provider 各配一条并测试通过（延迟与维度校验）；api_key 库内密文、接口回显 `sk-***last4`；旧 llm_config 读取方 grep = 0；抽取链路用新配置真实跑通一次。

### M3 · 解析管道与两阶段构建（需求 3/4 核心，最重）

**任务**（建议拆三波投喂）
- 波 1 文档链路：02 §3.4 迁移（R4）→ MinIO client + 上传/秒传/预签名 → `adapters/parsing.py`（docling 首选 + 现有 parser 兜底 + 扫描件判定 §2.2）→ `adapters/chunking.py`（中文分句 + 2000/15%）→ parse 队列 + SSE → 旧 `/api/v1/files`、upload/parse-files 端点删除收编（03 §18）。
- 波 2 构建+治理：02 §3.5/3.6 迁移（R5）→ blob→行表三阶段双写与回填（02 §4）→ `adapters/extraction.py` + `schema_gate.py`（04 §3/§4，含 14 缺陷 P0×4 修复）→ extraction API + Celery 任务 + SSE → `resolution.py` 三层消解 + `conflicts.py` 5 类检测（04 §5/§6）→ `provenance.py`（evidence 定位）→ `review_service.py` + 审核 API（03 §10）。
- 波 3 版本发布+前端：02 §3.7 迁移（R6）→ `versioning.py`（版本/diff/回滚/双时间轴）→ publish_service（门禁/快照/只读拦截）→ 版本/发布/审核 API 全量 → 前端：BuilderPage 拆分（05 §7）四 Tab + 审核工作台 `/reviews` + 时间轴页 → 金样本回归集（04 §12）入 CI。

**验收**：04 §13 全部勾选（扫描件端到端 <10min、两阶段交互不变、消解 F1≥0.85、审核 8 触发/状态机/发布门禁、回滚后三存储对账一致、金样本回归绿）；旧抽取同步代码路径删除（缺陷 #12）；契约测试权限矩阵全绿。

### M4 · 图谱可视化与存储闭环（需求 5/6）

**任务**（06 §13 a/b/c 三波）
- a：graph-view API（03 §13，nodes/edges 游标 + 双向边服务端判定 + neighbors/path/communities）→ `features/graph-explorer` 骨架（Sigma 装载 + FA2 Worker + LOD）替换实例探索 Tab。
- b：outbox_events 消费链（02 §5：worker-graph 同步 Neo4j/Milvus，worker-rdf 写 Oxigraph 四命名图）→ API 进程对 Neo4j/Milvus 的直写全部移除 → 中文渲染三件套（chip/形状/着色）+ 图例 + 交互集 → 资产中心只读 Sigma 复用。
- c：>25k 服务端预布局（graph_layouts 表 + Celery 任务）→ 删除 D3ForceGraph/OntologyCanvas 等 4 文件 → 性能与快照测试（06 §12.2）。

**验收**：06 §12.2 表格全过（500 节点 0.8s/60fps…确定性 diff=0）；杀 worker 重启 outbox 续跑无丢失；SPARQL 查四命名图正确；公共资产页从发布快照渲染且无写控件。

### M5 · 工具层（需求 7）

### 4.3 防跑偏规则（投喂时随附）

- 需求蔓延：任何不在本期任务清单里的"顺手优化"，要求先列出征求同意再动。
- 契约漂移：发现设计文档与代码现实冲突时，**停下来报告**，不要悄悄改契约。
- 依赖升级：禁止升级 semantica/React/antd 版本；新依赖须说明用途与替代方案。
- 测试造假：禁止为过测试弱化断言；金样本回归数据禁止改动（只允许增补）。
