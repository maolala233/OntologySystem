# 05 · 前端设计与页面规格

> 前端为前后端分离 SPA（React 18 + antd 5 + Vite + Tailwind）。本册解决三件事：**设计系统**（消灭三处硬编码色板与 `!important` 泛滥）、**信息架构与页面规格**（新增审核工作台/管理后台，构建器拆为四 Tab）、**数据层规范**（引入 react-query + zustand，SSE 鉴权规范化）。
>
> 图谱可视化（Sigma.js 3 / semantica-explorer 方案）独立成册见 06。

### 1.2 组件规范

- 列表页统一：`PageHeader（标题+主操作）+ FilterBar + Table/CardList + 空态组件 EmptyGuide`。
- 抽屉（Drawer）用于详情/编辑，Modal 只用于短表单与确认；长流程（抽取向导）用 Steps + 独立路由段。
- 所有异步按钮必须有 loading；破坏性操作（删项目/删文档/回滚）必须 `Modal.confirm` 二次确认 + 输入确认文案（回滚）。
- 错误呈现：请求失败 → antd message（轻）或 Alert（页面级）；表单错误逐字段显示（后端 422 detail 映射）。

## 4. 数据层规范（`shared/api/`）

### 4.1 HTTP client（axios 实例改造）

```ts
// 保留 baseURL 运行时推断（client.ts:4-25）；新增：
- 请求拦截: Authorization Bearer（现有）+ Idempotency-Key（上传/抽取提交自动生成 uuid）
- 响应拦截: 401 → 尝试 refresh（单飞锁）→ 失败踢登录；403 → 按 error.code 分支
  （PUBLISHED_READONLY → 引导弹窗；MODULE_NOT_GRANTED → NoAccess）
- 错误统一解包 { error: { code, message, detail } }
- 类型生成: openapi-typescript 从后端 /openapi.json 生成 shared/api/schema.d.ts（CI 校验漂移）
```

### 4.2 react-query 约定

- queryKey 规范：`['projects', filters]`、`['project', id, 'graph', 'nodes', filters]`、`['reviews', queue filters]`。
- 变更后失效策略：抽取完成/审核裁决/发布 → `invalidateQueries` 精确前缀；画布编辑走独立持久化（不进 query 缓存）。
- 现状修复：删除 localStorage 业务存储（`project_${id}_schema_graph` 等 3 个 key）——骨架数据已在服务端行表；`window.shouldExtractInstancesAfterFileSelect` 全局 hack 改为 store 标志。

### 4.3 zustand stores

```
shared/auth/authStore        user, modules[], login/logout
features/builder/store       projectMeta, activeTab, selection, dirtyState(If-Match),
                             taskProgress(抽取任务), reviewBadge
features/builder/schemaStore 画布数据（nodes/edges + undo/redo 栈，zipline 不可用故自实现 50 步）
shared/ui/uiStore            siderCollapse, locale, theme
```

### 4.4 SSE 规范（`shared/hooks/useSSE.ts`）

```ts
const { events, close } = useSSE(`/api/projects/${id}/extraction/tasks/${taskId}/events`,
  { onProgress, onCompleted, onFailed })
// 内部实现: 先 GET /auth/sse-ticket?task_id= 拿一次性 ticket(60s)
//          → new EventSource(`${url}?ticket=${t}`)  —— 彻底替代 ?token= 长令牌明文
// 断线重连: ticket 失效自动重取（最多 3 次）；组件卸载 close()
```

事件消费统一映射到 builder store 的 taskProgress；问答流式（07 §5）复用同一 hook（POST 不支持 EventSource → 用 fetch + ReadableStream 解析 SSE 帧，封装 `useSSOFetch`）。

## 5. 国际化（需求 8）

- `react-i18next`：`shared/i18n/{zh-CN,en}/` 命名空间按 feature 拆分（builder/admin/common）。
- **zh-CN 为默认与唯一完整语言**；en 只覆盖导航/通用按钮（缺失键 fallback zh-CN），不阻塞发布。
- 既有代码迁移策略：新组件一律 `t()`；存量页面在触碰时顺带迁移，不做全量机械替换。
- antd `ConfigProvider locale` 与 i18n.language 联动；日期 `dayjs` zh-cn。

## 8. 性能与可访问性

- 路由级 `React.lazy` + Suspense（graph-explorer/reviews/admin 首屏无关分包）；构建目标 es2020。
- 长列表虚拟化：审核队列、实体树（>500 子节点）、文档分块列表。
