# 06 · 图谱可视化重构设计（semantica-explorer 方案落地）

> 回答"前端图谱展示不太行怎么办"：**移植 semantica-explorer 的图谱渲染层**（Sigma.js 3 + graphology 生态）替换现有 D3-force/SVG 实现，配套后端游标分页数据契约与服务端预布局。本册与仓库既有 `docs/图谱展示重构方案.md`（1098 行）同源同栈，是它的**收敛落地版**：补充了 API 契约编号（03 §13）、表结构（`graph_layouts`）、移植文件清单与里程碑归属。

---

## 1. 现状问题（代码证据，为什么必须换范式）

| # | 问题 | 证据 |
|---|------|------|
| 1 | DOM/SVG 渲染上限 ~1–2k 节点 | `D3ForceGraph.tsx` 每节点 `<g>` + 每边双 path（536-548 行含隐形热区）；`Neo4jNode.tsx:50-69` 每节点 80px div |
| 2 | tick 循环全量查询 + 任何状态变化重建整个 simulation | `D3ForceGraph.tsx:868-883`、`:891-945`（highlightNodeId 也在依赖里） |
| 3 | 布局不可复现 | `layoutUtils.ts:52-53` 的 `Math.random()` 噪声；D3 初始位置随机（363-364 行） |
| 4 | 孤立节点右抛 `maxX+150`，视觉断裂 | `layoutUtils.ts:64-80` |
| 5 | 中文标签截断 5–6 字；无 LOD（缩小即糊） | `truncateLabel(label, isClass?6:5)`（272 行）；无 labelBudget 机制 |
| 6 | 无搜索/过滤/邻域/路径/社区/fitView；高亮仅单节点 | 全文件无对应实现 |
| 7 | 两套图实现并存、色板三处重复；双向边前端判定分页即错 | OntologyCanvas（弃用未删）、`D3ForceGraph.tsx:798-824`、`OntologyCanvas.tsx:40-68` |
| 8 | 数据一次性整载（blob），expandAllInstances 无虚拟化 | `OntologyBuilderPage.tsx:1310-1344` |

结论（与既有方案一致）：**选错渲染范式，调参无解**，换 WebGL 渲染 + 后端分页投影。

## 2. semantica-explorer 技术解剖（为什么照它做）

- **栈**：React 19 + Sigma.js 3（`sigma` + `@sigma/edge-curve` + `@sigma/node-border`）+ graphology（`graphology-layout-forceatlas2` Web Worker、`graphology-communities-louvain`、`graphology-shortest-path`、`graphology-metrics`）+ React Flow 12（本体画布）+ vis-timeline + Monaco。
- **架构**：Explorer 是"FastAPI 进程 + 随 PyPI 分发的 React 构建产物"，**无 npm 组件库**——不能整站嵌入（其 Python 后端是内存会话图、单 API Key、无多租户，与平台权限模型冲突）。**正确姿势：移植前端渲染模块 + 对接平台自有 API**。
- **与本平台栈的兼容**：Sigma 3 兼容 React 18（不阻塞）；React Flow 11（现用）保留做骨架编辑，不升 12（避免双升级风险）。

## 3. 目标架构：双模式图谱

```
features/builder/schema/   ReactFlow 画布 —— TBox 骨架编辑（连线/拖拽/属性抽屉）
features/graph-explorer/   Sigma.js 3   —— ABox 实例探索 + 只读快照浏览（大图）
                 ┌── graphConfig（比例尺/色板/形状映射，共享）
数据层：GET /graph/meta|nodes|edges（游标分页，7+9 字段契约）
        + neighbors / path / communities / layout（03 §13）
```

- 骨架编辑保留 ReactFlow（05 §6.5）——它需要 Handle 连线，Sigma 不适合编辑。
- 实例探索/公共资产/检索结果全部走 Sigma（同一组件复用三处：构建器 Tab、资产详情、审核证据跳转）。
- **删除**：`OntologyCanvas.tsx`、`StraightEdge.tsx`、`Neo4jNode.tsx`、`layoutUtils.ts`、`D3ForceGraph.tsx`（M4 末；期间与 Sigma 并存于不同 Tab，不共存同屏）。

## 4. 数据契约（前后端唯一接口，03 §13 实现）

### 4.1 节点（7 字段）

```ts
interface GraphNode {
  id: string        // uri 或行表 id 字符串
  label: string     // 完整中文标签（不截断，渲染层管预算）
  kind: 'class' | 'instance' | 'action_class' | 'action_instance'
  group: string     // 着色分组键（着色字段切换时由前端映射，见 §6.2）
  degree: number    // 服务端预计算（节点大小映射）
  x?: number; y?: number  // 服务端预布局时有值
}
```

### 4.2 边（9 字段）

```ts
interface GraphEdge {
  id: string; source: string; target: string
  label: string            // 谓词（LOD 下不常显，hover/inspection 显示）
  kind: 'relation' | 'type' | 'action'
  directed: boolean
  bidirectional: boolean   // ★ 服务端判定（同 (min(uriA,uriB), predicate) 分组计数>1）
  pairIndex: number        // 双向边序号（0/1），渲染层据此弧形偏移方向
  weight?: number          // 置信度，映射边宽
  group: string
}
```

### 4.3 分页与装载

- `GET /graph/nodes?limit=500&cursor=...`（默认首屏 500 节点：`ORDER BY degree DESC` 取"骨架 + 高度数实例"，其余按需 `neighbors` 展开）。
- `GET /graph/edges?limit=1000`：边在节点分页后按 `node_id IN (...)` 批量拉取，前端组装。
- 过滤参数：`class/status/source_doc/include=pending`——服务端 SQL 过滤（行表），而非前端隐藏。
- 装载流程：`meta → nodes×N 页 → edges → graph.import → 布局 → fitView`，全部 react-query 管理与缓存。

## 5. LOD 三级缩放（核心渲染策略）

| 档位 | 触发（camera ratio） | 节点渲染 | 标签 labelBudget | 边渲染 |
|------|---------------------|---------|-----------------|--------|
| overview | k < 0.5 | 全部（WebGL 点） | **4**（按 degree Top-N + 选中项） | 全部 1px，无箭头 |
| structure | 0.5 ≤ k < 2 | 全部 | **20** | 可见边 + 弧形双向偏移；箭头仅高亮邻域 |
| inspection | k ≥ 2 | 全部 + 边 hover 热区 | **60**（可视区域裁剪后 Top） | 全量（含箭头/标签 chip） |

- **labelBudget 是硬预算**（不是阈值开关）：每帧按 `degree*visiblePriority` 排序取前 N，选中/hover/搜索命中强制入选。
- 边同理参与 LOD：structure 档以下 `kind='type'` 边淡出（类型边是重复噪音）。
- `showContextualArrows`：箭头只画"关注节点"（选中/hover/搜索命中）的出边，避免万箭齐页。

## 6. 中文渲染规范（Canvas2D 标签 chip）

### 6.1 标签 chip（替代 DOM 文本与 SVG text）

- `@sigma/node-border` 自绘程序化节点 + Canvas 2D 圆角标签片（label renderer 重写）：底色 chip + 文字，取代"80px 圆 + line-clamp"。
- 字体：**先设字体再 measureText**；`PingFang SC / Microsoft YaHei`、最小 11px、weight 400、letter-spacing 0.02em。
- chip 宽度 = `measureText(label).width + 12px`；**不再按 5–6 字截断**——由 labelBudget 控制数量，单标签按画布宽度省略号截断（≥16 字）。
- hover 卡（inspection 档）：节点旁浮动卡片显示属性前 5 条 + 来源文档（SVG/HTML 混合，复用现有 tooltip 数据源）。

### 6.2 语义着色（信息熵自动选字段）

- 候选着色字段：`domain / nodeType / class_label / source_doc / confidenceBand`（**平台字段**，不移植 Explorer 的英文生物医学字段表）。
- 前端按字段值分布计算归一化信息熵，熵最高（区分度最好）者默认着色；用户可在工具栏切换。
- `semanticBaseColor` 快照：交互高亮色不污染基色（着色计算只读快照）。
- 图例：只统计**当前可见**节点（分页+过滤后），`group+color` 复合键，点击图例项=过滤切换。

### 6.3 深色图谱主题

```
bg #0F1420 · 网格 #1A2233 · 节点默认 #5B8DEF · 边 #2A3550 · 文字 #E6EAF2
语义色板(8): #5B8DEF #34C3A4 #F2B950 #EF6F6C #B585F2 #5AC8FA #A3B18A #F28CB1
（对比度全部 ≥ 4.5:1，经 WebAIM 校验）
```

## 8. 布局方案（确定性 + 自适应）

### 8.1 ForceAtlas2（主力，Web Worker）

```ts
settings = {
  slowDown: { 20: 12, 200: 8, 2000: 4 }[min(nodeCount, 2000)],  // 节点越多越慢越稳
  gravity: 0.6, scalingRatio: nodeCount > 500 ? 4 : 2,
  barnesHutOptimize: nodeCount > 1000, barnesHutTheta: 0.9,
  edgeWeightInfluence: 0.5, adjustSizes: true,
}
// 运行在 Worker（graphology-layout-forceatlas2/worker）；迭代 300 步后自动停
// “节点间距”滑杆映射 scalingRatio(1–8)；每次布局参数快照进 graph_layouts.params
```

### 8.2 确定性小组件网格布局（≤48 节点时）

替换"随机噪声 + 孤立节点右抛"：

```
1. 连通分量 BFS 分组（graphology connected components），分量按 [度序列, 首节点 uri] 字典序排序
2. 分量内：度排序环形排布（半径 96，中文 chip 更宽松）
3. 多分量：居中螺旋网格摆放（列距 320，行距 240），大分量居中
4. 全程无 Math.random；同输入必同输出（快照对比测试保证）
```

### 8.3 布局选择

节点 ≤48 且坐标覆盖率 <92% → 网格布局；否则 FA2。用户手动"重新布局"可切换。种子项目快照对比测试：两次布局坐标差 = 0。

## 10. 三级性能策略与后端配套

| 节点规模 | 策略 | 依赖 |
|----------|------|------|
| ≤ 8,000 | 实时 FA2（Worker）+ 前端 LOD | 现有 API 即可 |
| 8,000 – 25,000 | 分阶段装载（先骨架+Top5000，其余后台追加）+ FA2 渐进 + 渲染节流（rAF 合帧） | `graph/meta` 报告规模 |
| > 25,000 | **服务端预布局**：Celery graph 队列跑 FA2（python-graphology 等价实现或 networkx spring），坐标写 `graph_layouts`（MinIO JSON），前端直接用 x/y 免布局 | `POST /graph/layout`、`graph_layouts` 表 |

- 布局参数前后端共享同一份配置对象（`params` JSON 快照），保证预布局与实时布局视觉一致。
- 预布局任务在 instance 抽取完成 outbox 链末自动触发（>25k 时）。
