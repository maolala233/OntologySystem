# 16 - 前端体验优化方案

> 2026-10-25 起草。docs/15（S16-S25）是后端为主的本体平台可信化路线；本方案是其前端配套 + 独立体验优化，编号 FE1-FE12。
> 现状基线：React SPA ~11.4k 行 TSX；Builder 页签（SchemaTab 活编辑器 / GraphTab / DocumentsTab / Reviews / Timeline / CqPanel）；画布 D3 力导；Copilot Widget（提案卡/工具步骤/合规预检卡/澄清卡）；QA 抽屉（Markdown 答案 + [n] 溯源卡）；Scorecard / Reports / McpConsole / Admin 四页。
> UI 既有约定：实例蓝 #5B8DEF、类紫 #B585F2；面向非专业用户的人话文案；多选+全部+分页 50-100-200；键盘流无门槛。

## 0. 设计原则

1. **信任要看得见**：后端做的 provenance/证据/门禁/配对评估，每一项都要有对应的可视化载体——"可信"是演示出来的，不是接口字段。
2. **等待要被设计**：LLM 单调用 5-10 分钟是现实，一切慢操作的等待体验（进度、可离开、完成通知）按一等公民设计。
3. **三态规范**：所有数据区必须有加载态/空态/错误态，空态即文档（空状态里放"下一步做什么"的引导，不放空白插画）。
4. **确定性优先展示**：把机检结论（门禁/覆盖率/回退）放在人工判断之前——先给结论再给材料，符合非专业用户阅读顺序。

## 2. 分组详设

### A. 信任可视化（答辩核心，对应"运行时更可信"的可见形式）

**FE1 溯源升级：证据链面板**（`SourceCard.tsx` 升级 + 新 `EvidenceChain.tsx`）
- 现状：[n] 角标 → SourceCard（65 行，只有来源名/片段）。
- 升级：点击 [n] 侧滑**证据卡**：来源文档 + 页码 + 原文段落（解析时留存）+ OCR/VL 提取块原文 + validation_method（"原文摘录 / 数据探查 / 人工认定"标签）。
- 所有出现证据引用的地方统一组件：QA 答案角标、类/关系/公理详情抽屉、审核面板、copilot 提案卡——一处实现（`EvidenceChain`），四处挂载。
- 证据卡内"跳转原文"：打开文档预览并高亮对应页/块。
- 验收：任意一条公理可三步内看到"谁抽的（provenance 徽标）→ 谁认证的（认证徽标）→ 凭什么（证据原文）"。

**FE2 合规预检可解释化**（`VerifyReportCard.tsx` 升级）
- 现状：合规预检已有琥珀警告卡；升级为**推理链视图**：命中公理编号 → 公理内容 → 关联证据 [n] → 结论（阻断/警告）→ 修改建议，逐行展示，机检结论在前、解释在后。
- 阻断项红色 / 警告琥珀 / 通过绿色，与后端 severity 对齐；每行可展开看证据。
- 验收：走查"80 万欧元大额拦截"场景，用户不读文档也能看懂为什么被拦。

**FE3 发布门禁向导**（`PublishDialog.tsx` 升级为三步向导）
- Step1 预检报告：Tier1 阻断项（红色列表，点击定位到问题资产——跳 SchemaTab 对应类/公理）、Tier2 成熟度分数卡（RR/深度/孤立类，仪表+人话解读"关系丰富度偏低：本体基本只是分类树"）、Tier3 开关（默认关 + 数据外发提示）；
- Step2 变更摘要：与当前线上版本 diff（新增/修改/删除计数 + 明细列表）；
- Step3 确认发布：发布后 toast 显示下游刷新进度（Milvus/图缓存，幂等可重试）。
- 验收：构造含分类环的版本走发布 → 阻断列表可点击定位；正常发布全程不离开向导。

### B. 构建流体验（面向非专业用户）

**FE4 新手引导与空状态体系**
- 新项目首进 Builder：三步引导卡（传文档 → 审抽取 → 发布服务），可跳过、可从帮助按钮重开；
- 全局空状态组件：空态 = 一句人话 + 主操作按钮（"还没有类——从文档抽取开始"按钮直达 DocumentsTab）；
- SchemaTab 首次打开的免责提示已有（未保存提示），补"字段含义"tooltip 层。
- 验收：新账号从零到完成一次抽取-发布，无外部文档辅助可走通。

**FE5 慢任务体验统一**（`TaskProgressModal.tsx` 升级 + 全局任务中心）
- 抽取/推理/公理抽取等长任务统一为：**可关闭的后台任务条**（右下角浮层，不阻塞操作）+ 分阶段进度（解析→OCR/VL→抽取→合并，阶段名用动词短语）+ 完成系统通知（浏览器 Notification）+ 失败可重试；
- 任务中心（Navbar 铃铛）：历史任务列表、状态、耗时、入口跳转。
- 验收：发起抽取后关闭弹窗继续编辑画布，任务完成后收到通知并跳转结果。

**FE6 审核工作台升级**（`ReviewsPage.tsx` / `reviewShared.tsx`）
- 认证位可视化：每条候选带 provenance 徽标（AI / 规则 / 人工）+ 证据角标；
- **diff 视图**：重跑产生的"机器建议 vs 已认证值"左右对比（S16 建议区的前端载体），一键采纳/忽略；
- 批量流：筛选（类型/来源/置信度）→ 多选 + 全选 → 批量认证，键盘流（j/k 移动、空格选中、a 认证、x 拒绝）——沿用既有键盘流偏好；
- 审核进度条：本批已审/总数。
- 验收：100 条候选批量审核不碰鼠标可完成主干流程。

### C. 画布与浏览

**FE7 画布体验**（`OntologyCanvas.tsx` / `D3ForceGraph.tsx` / `DetailDrawer.tsx`）
- 性能：>80 类时力导模拟降档（冻结早期迭代 + 仅拖拽局部重算），节点数显示上限与聚合入口（按域折叠）；
- 聚焦模式：双击类 → 高亮一跳邻域、其余淡化（80 类全图对非专业用户是噪声）；
- 图例常驻（蓝=实例 紫=类 绿=规则区 紫区=公理，颜色语义固定）；
- DetailDrawer 补证据区（挂 FE1 组件）与公理列表（命中该类的公理）。
- 验收：158 类项目画布可流畅拖拽；聚焦模式演示"围绕跨境汇款的语义邻域"。

**FE8 全局命令面板 Ctrl+K**
- 一处搜索全站：类/实例/公理/规则/页面/项目，键盘上下选择直达（类→打开 SchemaTab 并定位；实例→打开 DetailDrawer）。
- 数据源：现有列表接口聚合，前端索引缓存。
- 验收：任意页面 Ctrl+K → 输入"跨境" → 直达类详情 ≤2 秒。

### D. Copilot（运行时可信的对话面）

**FE9 提案 diff 预览与撤销**（`ProposalCard.tsx` 升级）
- 应用前 diff：提案将产生的画布/Schema 变更以 +/- 行内 diff 预览（新增类/连边/属性变化）；
- 批量应用进度（多提案按依赖顺序，已有 S15 基础）：应用中逐张卡打勾；
- **一键撤销**：应用后 toast 提供"撤销本次全部应用"（后端有审计链路，前端补入口 + 确认弹窗）。
- 验收：一次多提案应用后可完整回滚到应用前状态。

### E. 问答（FE10，依赖 S19/S20 接口）

**FE10 QA 抽屉体验升级**（`QaDrawer.tsx` 439 行拆分 + 交互升级）
- 流式输出（SSE 已有基础则用，否则分段渐显）+ 回答前显示"检查覆盖中…"（S20 预检的可见化）；
- **诚实信号呈现**：覆盖不足时渲染"未覆盖提示卡"——"以下概念本本体未覆盖：…（建议澄清/去构建）"，按钮直达澄清选项或抽取页（不硬答的体验闭环）；
- [n] 角标挂 FE1 证据卡；答案底部加"本回答依据版本 ontology_vN"；
- QaDrawer 拆分为 `AnswerStream / CoverageNotice / EvidenceList / FollowUpBar` 子组件。
- 验收：否定题回答附证据；未覆盖问题走澄清而非硬答；答案带版本角标。

### F. 进化可视化（FE11，依赖 S22——答辩差异化画面）

**FE11 进化页：状态机 + 评估对比**（TimelineTab 扩展或新 EvolveTab）
- **状态机视图**：running（第 N 轮）→ 逐轮卡片（假设、候选版本、评估结果、accept/reject 徽标）→ 终态；checkpoint 与触发条件（30 条轨迹 / 7 天）进度条可见——"进化是受控的"一眼可见；
- **评估对比视图**：Parent vs Candidate 40 题逐题对比条形图（改善绿/回退红/持平灰），顶部总分与"无不可接受回退"声明徽标；否定题单独分组；
- 门禁结论卡：由代码重算的 accept/reject 结论 + gate_input 快照时间（强调"结论是机算的"）。
- 验收：走查一轮 reject + 一轮 accept，页面完整呈现两轮与最终发布。

### G. 演示模式（FE12，答辩现场保险）

**FE12 演示模式**（Navbar 开关 + `DemoGuide.tsx`）
- 开关打开后：预置演示项目置顶、示例问题一键发送（含"80 万欧元大额拦截"完整脚本）、隐藏实验性入口、字体/对比度微调（投影友好）；
- 演示脚本条：侧边步骤清单（1 传文档 2 审证据 3 发布门禁 4 Agent 查语义 5 大额拦截 6 进化对比），点击步骤高亮对应页面入口——现场照着走不迷路。
- 验收：新环境导入演示项目 + 开演示模式，全程照清单走完 6 步无卡点。

## 4. 设计系统落地规范（随 FE 逐项沉淀）

- **色板**：实例 #5B8DEF / 类 #B585F2 / 通过绿 / 警告琥珀 / 阻断红 / AI 徽标灰蓝 / 人工徽标紫，写入 `colors.ts` 单一来源；
- **文案**：人话规范——按钮动词开头（"去抽取""认证这条"），机检结论一句话+详情折叠；禁"失败"裸奔（失败必带下一步：重试/查看日志）；
- **三态**：`<DataState loading error empty>` 统一组件，空态必带主操作；
- **交互默认**：多选+全部+分页 50-100-200；键盘流；破坏性操作双确认 + 可撤销优先于确认弹窗；
- **走查**：每 FE 交付配一次浏览器走查（web-gui-tester），回归脚本存 temp/。
